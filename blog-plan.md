# MDX Blog Implementation Plan

## Overview

A GitHub-hosted MDX blog integrated into a Next.js portfolio site. Posts metadata is served via a pre-built `blog-index.json`, individual posts are fetched on-demand from GitHub using the Contents API, rendered server-side with `next-mdx-remote`, and cached via ISR. Images are hosted on Cloudinary. A GitHub Action auto-updates the index on every push.

---

## Architecture at a Glance

```
GitHub Repo (blogs/)
      ↓  push triggers GitHub Action
blog-index.json (auto-generated, committed to repo)
      ↓  one fetch for listing page
Next.js App Router
      ↓  fetch individual MDX only on post open
next-mdx-remote (MDX → HTML)
      ↓  ISR Cache
User Browser (SEO-ready HTML)

Images → Cloudinary CDN (public URLs in MDX frontmatter)
```

```
blog-repo/
├── blogs/
│   ├── getting-started-with-mdx.mdx

│   └── ...
├── blog-index.json                  ← auto-generated, never edit manually

```

### Each MDX File Structure

```mdx
---
title: "Getting Started with MDX"
date: "2026-05-11"
description: "Learn how to combine Markdown with React components using MDX."
tags: ["MDX", "React", "Web Development"]
coverImage: "https://res.cloudinary.com/your-cloud/image/upload/v1/blog/cover.webp"
published: true
---

Your blog content goes here...

![Alt text](https://res.cloudinary.com/your-cloud/image/upload/v1/blog/image1.jpg)
```

- **Filename = slug** (e.g., `getting-started-with-mdx.mdx` → `/blog/getting-started-with-mdx`)
- `slug` field in frontmatter is redundant — derived from filename, don't include it
- `published: false` = draft, excluded from index and listing
- All images are Cloudinary public URLs — no local image management needed

## Implementation Steps

### Step 1 — GitHub Action Script (`scripts/generate-index.js`)

Runs automatically on every push to `main`. Logic:

- Reads all `.mdx` files in `blogs/`
- Parses frontmatter from each using `gray-matter`
- Filters out `published: false` drafts
- Sorts by date descending
- Writes `blog-index.json` to repo root
- Commits and pushes the updated JSON back to the repo

GitHub Action trigger (`.github/workflows/generate-index.yml`):

```yaml
on:
    push:
        paths:
            - "blogs/**.mdx"
```

Only triggers when an MDX file changes — not on every push.

---

### Step 2 — GitHub Contents API Utility (`lib/github.ts`)

Two functions:

**`getAllPosts()`**

- Fetches `blog-index.json` from GitHub Contents API — **one single API call**
- Decodes base64 content, parses JSON
- Returns array of post metadata ready to render
- Used by listing page, sitemap, RSS feed

**`getPostBySlug(slug)`**

- Fetches `blogs/${slug}.mdx` from GitHub Contents API
- Decodes base64, strips `\n` from base64 string before decoding
- Parses frontmatter with `gray-matter`
- Returns `{ content, frontmatter }` or `null` if not found

Both functions use:

- `Authorization: Bearer ${GITHUB_TOKEN}` header (server-side only)
- `next: { revalidate: 3600 }` on the fetch call for ISR

---

### Step 3 — Blog Listing Page (`app/blog/page.tsx`)

**Behavior:**

- Calls `getAllPosts()` — single fetch of `blog-index.json`
- Renders a grid of `BlogCard` components
- ISR revalidation: `export const revalidate = 3600`

**SEO:**

- `generateMetadata()` returns static metadata for the listing page
- Title: "Blog | Your Name"
- Description: "Articles about X, Y, Z"

---

### Step 4 — Individual Post Page (`app/blog/[slug]/page.tsx`)

**Behavior:**

- Calls `getPostBySlug(slug)` to fetch the MDX file
- Passes content through `next-mdx-remote/rsc`
- Renders `BlogPost` layout wrapping the MDX output
- ISR revalidation: `export const revalidate = 3600`

**404 Handling:**

- If `getPostBySlug` returns null → `notFound()` from Next.js

**SEO via `generateMetadata()`:**

```
title:        frontmatter title
description:  frontmatter description
openGraph:    title, description, coverImage, publishedTime
twitter:      card, title, description, image
canonical:    full post URL
```

---

### Step 5 — MDX Rendering (`components/blog/MDXComponents.tsx`)

Override default HTML elements with styled components:

| MDX Element  | Custom Component                          |
| ------------ | ----------------------------------------- |
| `h1, h2, h3` | Styled headings with anchor links         |
| `a`          | Opens external links in new tab safely    |
| `img`        | Next.js `<Image>` — src is Cloudinary URL |
| `code`       | Inline code with syntax highlighting      |
| `pre`        | Code block with copy button               |
| `blockquote` | Styled pull quote                         |

Add to `next.config.js` for Cloudinary images:

```js
images: {
    remotePatterns: [{ hostname: "res.cloudinary.com" }];
}
```

Rehype/Remark plugins:

- `rehype-pretty-code` + `shiki` — syntax highlighting
- `remark-gfm` — tables, strikethrough, etc.
- `rehype-slug` — auto IDs on headings
- `rehype-autolink-headings` — clickable anchor links

---

### Step 6 — Sitemap (`app/sitemap.ts`)

- Calls `getAllPosts()` (reads `blog-index.json` — one fetch)
- Returns all blog post URLs with `lastModified` from frontmatter date
- Served automatically at `/sitemap.xml`

---

### Step 7 — RSS Feed (`app/feed.xml/route.ts`)

- Calls `getAllPosts()`, formats each into an RSS item
- Served at `/feed.xml`

## Caching Strategy

| Page         | Revalidation | Reason                                    |
| ------------ | ------------ | ----------------------------------------- |
| Blog listing | 1 hour       | blog-index.json updates within an hour of push |
| Blog post    | 1 hour       | MDX edits propagate quickly               |
| Sitemap      | 1 hour       | Stays in sync with blog-index.json             |

---

## Image Workflow

1. Upload image to **Cloudinary** (drag and drop in dashboard)
2. Copy the public URL
3. Paste directly into MDX frontmatter (`coverImage`) or inline in content
4. Done — Cloudinary handles CDN, optimization, resizing

No images live in the portfolio repo. No `public/images/blog/` folder to manage.

---

## Publishing Workflow

```
Write post in VS Code
        ↓
Create blogs/your-post-slug.mdx with frontmatter
Upload images to Cloudinary, paste URLs in MDX
        ↓
git add . && git commit -m "new post: your title"
        ↓
git push origin main
        ↓
GitHub Action runs → updates blog-index.json → commits back
        ↓
Post is live within 1 hour (ISR revalidation)
```

## Summary

Push an MDX file → GitHub Action updates `blog-index.json` → Next.js fetches it in one call for the listing page → fetches individual MDX only when a post is opened → ISR caches everything at the edge. Images live on Cloudinary, referenced by URL. No rebuild, no CMS, no cost, no clutter.
